# Ambig-DS: A Benchmark for Task-Framing Ambiguity in Data-Science Agents

## Abstract
As data-science agents shift from co-pilots to auto-pilots, silent misframing becomes a critical failure mode. Agents quietly commit to plausible but unintended task framings, producing clean, executable artifacts that hide their incorrect assessment of the task. Existing benchmarks score whether the pipeline runs, ignoring whether the agent recognized the task was underspecified. We introduce Ambig-DS, two diagnostic suites — one for prediction-target ambiguity (Ambig-DS-Target, 51 tasks built on DSBench, a tabular modeling benchmark) and one for evaluation-objective ambiguity (Ambig-DS-Objective, 61 tasks built on MLE-bench, a Kaggle-style ML competition benchmark) — constructed so that scoring uses each source benchmark's original evaluator. For every task we pair the original, fully specified version with an ambiguous variant produced by controlled edits; a human-and-LLM verification pipeline confirms each variant admits multiple plausible interpretations with decision-relevant consequences. The suites are analyzed independently and ambiguity lowers performance in both. Across five agents spanning efficient to frontier-class models, we find in our controlled diagnostic setting: (i) failures are silent commitments — wrong-target submissions on Target, wrong-metric or non-committal baseline submissions on Objective — rather than execution errors; (ii) allowing the agent to ask one clarifying question recovers much of the loss under idealized conditions, suggesting missing framing information drives a substantial part of the observed degradation; but (iii) agents cannot reliably tell when to use it: permissive prompts induce over-asking on clear tasks, while conservative prompts induce silent defaulting on ambiguous ones. Recognizing target and objective underspecification, not pipeline execution, is the bottleneck missing from standard DS-agent evaluations.

## Methods

### Problem Setup
A data-science agent receives an observation o = (p, d) consisting of a prompt p and data package d. To act, it must commit to a framing: the discretionary choices that turn o into a well-posed supervised-learning problem (target, objective, output form, prediction-time feature availability, permissible external information, etc.). The paper focuses on two representative variables, θ = (T, M), where T specifies the prediction target and M specifies the evaluation objective together with the implied output form (e.g., calibrated probabilities vs. hard labels, ranking vs. pointwise scores). These are chosen because they are (i) directly tied to the source-benchmark evaluator, so misframing is scorable without changing the scoring rule; and (ii) controllable through minimal prompt–data edits. θ⋆ denotes the intended framing, θ̂ the framing the agent commits to.

Let C(o) be the set of framings admitted by o under a verification protocol Π (a four-item human-and-LLM checklist: plausible alternatives, ambiguity preservation, decision relevance, task preservation). The fully specified source observation o⋆ satisfies C(o⋆) = {θ⋆}; a constructed observation is ambiguous if |C(o)| > 1. An unflagged misframing occurs when the agent acts without clarification and commits to θ̂ ≠ θ⋆. A well-calibrated agent satisfies: ask iff |C(o)| > 1; commit to θ⋆ when C(o) = {θ⋆}. Ambig-DS evaluates deviations from this rule via paired (Full, Ambig., Ask) conditions.

**Two concrete instances.** Target (bike-sharing-demand, DSBench): the original prompt says "predict count" with a `count` column; the ambiguous variant renames it to `val_1`, adds a calibrated decoy `val_2`, and rewrites the prompt to "predict value" — only `val_1` is scored. Objective (aerial-cactus-identification, MLE-bench): the original prompt evaluates by ROC-AUC with format `id,has_cactus`; the ambiguous variant keeps data, target, and submission format identical but replaces the metric sentence with "a standard evaluation procedure for this task," so the agent does not know whether to submit probabilities or hard labels.

### Benchmark Construction
A five-stage pipeline (source task → screen executable & transformable → generate ambiguous variants → verify via LLM + human review → package ambiguous + full with evaluator) builds both suites. Screening retains DSBench tasks with a single clean target column and MLE-bench tasks fitting the harness storage limit (50 GB).

**Ambig-DS-Target (DSBench).** Built on DSBench because its tabular tasks typically expose a single explicit target column. Coordinated prompt–data interventions rename the true target column to `val_1` or `val_2` (randomized: val_1 correct in 31 cases, val_2 in 20) and add a second candidate target with the other name; sample submission headers are genericized (e.g., `id,prediction`); neither candidate appears in the test split. The decoy target is constructed to be plausible rather than an obvious distractor: a score vector is built from weakly correlated visible features (bottom ~70% by |ρ_Spearman(·, y)|, clamped to [4,40]), training rows are sorted by this score, and true-target values are assigned in the same sorted order, giving the decoy the same marginal distribution as the true target but driven by different features. Per-task calibrated label noise (label swapping for classification; Gaussian noise + re-rank-mapping for regression) is binary-searched to equalize the 3-fold HistGradientBoosting predictability of decoy vs. true target within a tolerance (29/51 tasks meet a 0.02 gap, 40 meet 0.05, 44 meet 0.10). The prompt is then edited (via Claude Opus 4.7) to remove target-identifying language while preserving the task.

**Ambig-DS-Objective (MLE-bench).** Built on MLE-bench because its competitions make the metric central to model selection, thresholding, and formatting. Prompt-only interventions (via Claude Opus 4.7) keep data, target definition, submission format, and evaluator fixed but remove explicit metric references, replacing them with generic performance language; the target stays specified while the optimization objective is underspecified. The set spans 27 higher-is-better and 12 lower-is-better tasks across metrics including log loss, ROC-AUC variants, word-level Jaccard, accuracy, RMSE/RMSLE, MAE, MAP@K, label-weighted label-ranking average precision, Pearson correlation, Levenshtein rate, and custom geometric distance.

**Verification and filtering.** Both suites use the same checklist, applied via LLM verification and human review: (1) plausible alternatives — at least two reasonable candidate framings; (2) ambiguity preservation — alternatives remain plausible considering both edited prompt and data; (3) decision relevance — resolving the ambiguity changes a task-level choice (target, output type, criterion, thresholding, submission semantics); (4) task preservation — only ambiguity-inducing information is removed. A cross-family LLM-verifier audit (non-Claude verifiers) confirms broadly similar agreement with final human-reviewed labels.

**Clarification oracle.** Each released task ships with a scoped, truthful clarification channel used under the Ask condition. Before modeling (and without fitting/evaluating models), the agent writes one self-contained question of ≤50 words, or NONE, and stops. Claude Haiku 4.6 answers under a restricted answer-only protocol: for target ambiguity it answers only the literal question and reveals the target only if asked (no test statistics, CV diagnostics, construction internals, code, or modeling advice); for objective ambiguity it is restricted to metric, scoring, and submission-format information. Out-of-scope requests receive a fixed refusal. This is a causal probe of whether missing framing information suffices when delivered perfectly, not a deployment estimate of realistic stakeholder interaction.

### Experimental Setup
Code-based agents are evaluated in the OpenCode framework, spanning efficient models (Gemini 3 Flash, GPT-5.4 Nano, Claude Haiku 4.5) to frontier-class models (Gemini 3.1 Pro, GPT-5.4), with equal tool access, execution environment, and per-suite wall-clock budget (2h Target, 24h Objective; oracle round-trip excluded).

**Evaluation conditions.** Full: original fully specified task. Ambig.: ambiguous variant, no clarification oracle available (agent may still flag/abstain but is not invited to ask). Ask: ambiguous variant with the clarification oracle (one ≤50-word question or NONE, then stop until answered).

**Task performance.** Scored with the original source-benchmark evaluator (DSBench score for Target; MLE-bench competition score for Objective), normalized to [0,1]. Δambig = S_ambig − S_full; Δask = S_ask − S_ambig, macro-averaged across tasks. Invalid and Timeout runs score 0 and remain in the denominator. One-sided paired Wilcoxon signed-rank tests (Full > Ambig.; Ask > Ambig.) and paired bootstrap 95% CIs are reported.

**Ask behavior.** Two rates are reported: Ask on Ambig. (desired behavior) and Ask on Full (unnecessary asking). An ask is any non-NONE question written to `_question.txt`.

**Framing diagnostics.** For Target ambiguity, valid submissions are labeled by whether they optimize the intended or alternative target. For Objective ambiguity, five LLM-judge calls with majority vote classify each run as intended-objective, alternative-objective, degenerate, or invalid/no-score, with human verification. Only valid alternative-framing runs count as unflagged misframings.

## Results

### Ambig-DS-Target (DSBench)
Even frontier backbones (Gemini 3.1 Pro, GPT-5.4) submit a plausible alternative target on 39–63% of ambiguous DSBench runs without flagging the underdetermination; smaller backbones misframe at 43–59%. A trace/answer recognition audit shows user-overridable flagging in the final answer never exceeds 4% even when traces acknowledge the ambiguity, so the silent-commitment characterization holds at the answer-facing level. Δambig ranges from −0.10 to −0.29 across models; all five bootstrap CIs exclude zero (tightest: GPT-5.4 Nano, [−0.18, −0.02]); all paired Wilcoxon tests for Full > Ambig. are significant.

### Ambig-DS-Objective (MLE-bench)
Ambiguity degrades performance: Δambig ranges from −0.04 to −0.09 (15–35% of Full); all five bootstrap CIs exclude zero (tightest: GPT-5.4, [−0.06, −0.02]); all paired Wilcoxon tests for Full > Ambig. are significant.

Silent failures split into two modes sharing a silent-failure signature: unflagged misframing (Alternative Obj. — a substantive model optimized for a plausible but unintended objective) and unflagged abdication (Degenerate — a non-committal submission such as a copied baseline or constant prediction). Combined silent failure runs 16–62% under Ambig. across backbones (frontier: 46% Gemini 3.1 Pro, 19% GPT-5.4), splitting into 5–18% misframing and 8–49% abdication. Under Ask, Alternative Obj. drops to ≤4% everywhere, but Degenerate persists for weaker backbones — Ask kills misframing, not abdication.

### Cross-Suite Observations
The degradation-under-Ambig./recovery-under-Ask pattern holds in both suites and is not specific to Claude-family evaluated agents: restricting to the four non-Claude backbones preserves the qualitative pattern within each suite (every row shows Δambig < 0 and Δask > 0, all Wilcoxon tests significant at p < 0.05). Re-running Claude Haiku 4.5's Ask condition with a GPT-5.4 oracle shifts Δask from +0.20 to +0.18 on Target (unchanged on Objective); swapping the Objective judge from Claude to GPT shifts per-cell misframing by ≤4 pp (κ = 0.74) — recovery is not an oracle- or judge-family artifact.

Agents can use clarification when obtained but cannot reliably detect when to ask. Calibration varies substantially across models and policies: on Target, some combinations approach good calibration (e.g., Gemini 3.1 Pro under the conservative policy asks on 94% of ambiguous tasks and 0% of fully specified ones), while on Objective most agents collapse under the conservative policy (Claude Haiku 4.5 asks on only 5% of ambiguous metric tasks; GPT-5.4 Nano and GPT-5.4 ask on 0%). The permissive policy yields high recall on ambiguous tasks at the cost of high false positives on fully specified ones; the conservative policy reduces over-asking but suppresses legitimate asking. Over-asking under the permissive policy is dominated by style preferences, restatements of prompt information, and out-of-scope requests (e.g., 88% of Claude Haiku 4.5's asks on Target are style-preference questions; 85% of Gemini 3 Flash's asks on Objective are out-of-scope). Under-asking manifests as silently committing to a default framing rather than asking the wrong question — under the conservative policy, GPT-5.4 and GPT-5.4 Nano silently default on 100% of ambiguous metric runs, Claude Haiku 4.5 on 97%, while only 0–8% of asks ever target the wrong topic. Every model–policy pair evaluated shows miscalibration on at least one suite.

Recovery under the clarification oracle: Δask reaches +0.20 on Target and +0.09 on Objective; Ask essentially closes the Ambig.–Full gap on Objective but leaves a residual gap on Target, indicating residual execution failures persist even after framing is resolved.

## Conclusions
Ambig-DS isolates a failure mode that standard data-science benchmarks largely hide. In fully specified settings, a valid submission is often taken as evidence that the agent understood the task; under task-framing ambiguity this inference breaks down, since an agent can produce a coherent artifact while committing to a plausible but unintended target or objective. This separates pipeline-execution competence from task-framing competence.

The two suites yield distinct silent-failure signatures. Ambig-DS-Target produces discrete wrong-target misframings; Ambig-DS-Objective splits between substantive misframings (commitment to a plausible alternative objective) and abdications (retreat to a degenerate baseline or constant submission). Both are unflagged commitments under ambiguity rather than execution failures. Within each suite, the clarification oracle recovers much of the lost performance, indicating that missing framing information — not pipeline execution — drives the degradation. The non-trivial finding is not that recovery occurs but that agents cannot reliably detect when to invoke clarification.

Ambig-DS yields actionable signals for three audiences. Users should specify framing variables (target, metric, output type, submission semantics) explicitly: omitting them produces reliable and often large performance drops even from capable agents. Builders should treat ask–act calibration as a concrete post-training or prompt-engineering target, since prompt wording shifts the operating point but does not yield robust sensitivity to decision-relevant ambiguity. Benchmark designers should pair fully specified tasks with diagnostic ambiguous variants: pipeline-execution scores on fully specified tasks overestimate competence when framing is not guaranteed.

**Limitations.** Ambig-DS is a controlled diagnostic suite, not a census. It uses minimal interventions on existing benchmark tasks while preserving the original evaluator, and studies only two framing variables (T, M); other framing variables (information boundaries, data leakage, temporal assumptions, prediction-time feature availability, permissible external information) and richer naturalistic ambiguity are left for future work. Axis is confounded with source benchmark by design (Target on DSBench, Objective on MLE-bench), so effect-size differences across suites are not a causal comparison; each suite is interpreted independently. Construction and oracle are model-assisted (Claude Opus generation/verification, Claude Haiku oracle), mitigated via cross-family verifier audit, cross-family judge/oracle robustness checks, human review, and the non-Claude agent subset, though residual generation- and oracle-family effects cannot be fully ruled out. θ⋆ is a protocol scoring convention rather than the unique correct reading; the Ask oracle is intentionally idealized and should be read as an upper bound on recoverable performance; the dataset is modest in size (51 Target + 61 Objective paired tasks); and because the Ambig. condition has no clarification channel, Δambig does not fully separate non-recognition from commitment-under-recognized-ambiguity — a confound bounded at the trace level by the recognition audit. Ambig-DS estimates should be read as diagnostic evidence of failure modes under verified ambiguity rather than as prevalence over the space of all data-science tasks.
